Below is a **ready-to-run demo blueprint** you can stand up in your own Azure subscription that showcases exactly what the client is asking for: Azure API Management, Logic Apps, Azure Functions (PowerShell), Service Bus, secure data landing (ADLS Gen2 / Fabric link), CI/CD and IaC with **Bicep**. ## What the demo shows (in 3–5 crisp scenes)

1. **Secure API front door** with **Azure API Management** (APIM) validating JWTs, enforcing **rate limiting**, and fronting a Logic App + Function backend. (Policies: `validate-jwt`, `rate-limit-by-key`.) ([Microsoft Learn][1])
2. **Orchestration** with **Logic Apps (Consumption)** calling Dynamics 365 Finance (via OData or the Fin & Ops connector) and dropping messages on **Service Bus** for downstream processing. ([Microsoft Learn][2])
3. **Event‑driven integration**: a **PowerShell Azure Function** consumes Service Bus messages, transforms them, and lands data to **ADLS Gen2** (or to **Microsoft Fabric** via Dataverse Link, which is the supported path now that “Export to Data Lake” is retired). ([Microsoft Learn][3])
4. **Observability** wired up via **Application Insights + Log Analytics** and APIM diagnostics. ([Microsoft Learn][4])
5. **DevOps/IaC**: everything below deploys with **Bicep**, and I include one YAML snippet for CI/CD (Azure DevOps/GitHub). ([Microsoft Learn][5])

> **Note on D365 data export in 2025**
> Microsoft **deprecated** “Export to Data Lake” for Fin & Ops (Oct 2023), with retirement completed in 2025. For the analytics/landing zone storyline, your demo should mention **Synapse Link / Link to Microsoft Fabric** for F&O data via Dataverse instead of the old feature. ([Microsoft Learn][6])

## High‑level architecture

```
[Client] ──(OAuth2/JWT)──> [APIM]
   |  validate-jwt + rate-limit-by-key, KV-backed secrets
   v
[Logic App (Consumption)]
   |-- HTTP action to D365 F&O OData or Fin&Ops Connector
   |-- On success -> send to Service Bus (queue)
   v
[Service Bus Queue]  --->  [Azure Function (PowerShell)]
                                |-- transform + land to ADLS Gen2
                                |-- (or push into Fabric via Dataverse Link)
                                v
                          [ADLS Gen2] / [Fabric OneLake]
```

* **APIM** gives you the “API Management & RESTful interfaces” part with policy-based security and throttling. ([Microsoft Learn][1])
* **Logic Apps** demonstrate low‑code orchestration with D365 (OData or Fin & Ops connector). ([Microsoft Learn][2])
* **Functions (PowerShell)** highlight scripting skills + event processing via **Service Bus trigger** using **managed identity**. ([Microsoft Learn][3])
* **ADLS Gen2** provides the lake landing (and in the demo, mention **Fabric Link** as the modern alternative for near‑real‑time D365 analytics). ([Microsoft Learn][7])

## Deploy the foundation (Bicep)

> This single file creates Log Analytics, Application Insights, Key Vault, ADLS Gen2, Service Bus (Standard), APIM (Consumption, system‑assigned MI), and a Function App on **Flex Consumption** (recommended in 2025). **APIM** and **Function** identities are used for RBAC (no secrets). ([Microsoft Learn][8])

**main.bicep**

```bicep
param prefix string = 'd365demo'
param location string = resourceGroup().location

var suffix   = uniqueString(resourceGroup().id)

//
// Log + Observability
//
resource la 'Microsoft.OperationalInsights/workspaces@2022-10-01' = {
  name: '${prefix}-law-${suffix}'
  location: location
  properties: {
    retentionInDays: 30
    features: { enableLogAccessUsingOnlyResourcePermissions: true }
  }
}

resource appi 'Microsoft.Insights/components@2020-02-02' = {
  name: '${prefix}-appi-${suffix}'
  location: location
  kind: 'web'
  properties: {
    Application_Type: 'web'
    WorkspaceResourceId: la.id
  }
}

//
// Key Vault (RBAC mode)
//
resource kv 'Microsoft.KeyVault/vaults@2023-02-01' = {
  name: '${prefix}-kv-${suffix}'
  location: location
  properties: {
    tenantId: subscription().tenantId
    sku: { name: 'standard', family: 'A' }
    enableRbacAuthorization: true
    softDeleteRetentionInDays: 7
  }
}

//
// Storage for ADLS Gen2
//
resource st 'Microsoft.Storage/storageAccounts@2023-01-01' = {
  name: toLower('${prefix}st${suffix}')
  location: location
  sku: { name: 'Standard_LRS' }
  kind: 'StorageV2'
  properties: {
    isHnsEnabled: true // hierarchical namespace (ADLS Gen2)
    minimumTlsVersion: 'TLS1_2'
    allowBlobPublicAccess: false
  }
}

//
// Service Bus (Standard) + queue
//
resource sb 'Microsoft.ServiceBus/namespaces@2022-10-01-preview' = {
  name: '${prefix}-sb-${suffix}'
  location: location
  sku: { name: 'Standard', tier: 'Standard' }
}
resource sbq 'Microsoft.ServiceBus/namespaces/queues@2022-10-01-preview' = {
  name: '${sb.name}/inbound'
  properties: {
    maxDeliveryCount: 10
    deadLetteringOnMessageExpiration: true
  }
}

//
// APIM (Consumption) with system-assigned identity
//
resource apim 'Microsoft.ApiManagement/service@2022-08-01' = {
  name: '${prefix}-apim-${suffix}'
  location: location
  sku: { name: 'Consumption' } // lowest-cost, per-call; custom domain limited to gateway
  identity: { type: 'SystemAssigned' }
  properties: {
    publisherEmail: 'you@example.com'
    publisherName: 'Demo'
  }
}

//
// Function App (PowerShell) on Flex Consumption (Linux)
//
resource plan 'Microsoft.Web/serverfarms@2024-04-01' = {
  name: '${prefix}-fcplan-${suffix}'
  location: location
  sku: { name: 'FC1', tier: 'FlexConsumption', capacity: 1 }
  kind: 'functionapp,linux'
  properties: { reserved: true }
}

resource func 'Microsoft.Web/sites@2024-04-01' = {
  name: '${prefix}-func-${suffix}'
  location: location
  kind: 'functionapp,linux'
  identity: { type: 'SystemAssigned' }
  properties: {
    serverFarmId: plan.id
    httpsOnly: true
    siteConfig: {
      linuxFxVersion: '' // not required for PowerShell worker
      appSettings: [
        { name: 'FUNCTIONS_WORKER_RUNTIME', value: 'powershell' }
        { name: 'WEBSITE_RUN_FROM_PACKAGE', value: '1' }
        // Identity-based connection to Service Bus (fully qualified namespace)
        { name: 'AzureWebJobsServiceBus__fullyQualifiedNamespace', value: '${sb.name}.servicebus.windows.net' }
        // App Insights
        { name: 'APPINSIGHTS_INSTRUMENTATIONKEY', value: appi.properties.InstrumentationKey }
      ]
    }
  }
}

//
// RBAC: give the Function MI send/receive on Service Bus
//
resource roleSender 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(func.id, 'sb-sender')
  scope: sb
  properties: {
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', '69a216fc-b8fb-44d8-bc22-1f3c2cd27a39') // Service Bus Data Sender
    principalId: func.identity.principalId
  }
}
resource roleReceiver 'Microsoft.Authorization/roleAssignments@2022-04-01' = {
  name: guid(func.id, 'sb-receiver')
  scope: sb
  properties: {
    roleDefinitionId: subscriptionResourceId('Microsoft.Authorization/roleDefinitions', '4f6d3b9b-027b-4f4c-9142-0e5a2a2247e0') // Service Bus Data Receiver
    principalId: func.identity.principalId
  }
}

output apimName string = apim.name
output funcName string = func.name
output serviceBusQueue string = sbq.name
output storageName string = st.name
```

**Why these choices?**

* **Flex Consumption** is the recommended Functions plan in 2025 (fast scale, MI support, better networking). Use `sku.name=FC1`, `tier=FlexConsumption` and `reserved=true` (Linux). ([Microsoft Learn][8])
* **APIM Consumption** keeps costs tiny and still supports **JWT validation** and **rate limiting**. Custom domains are supported for the gateway only; VNet/private networking requires v2 Standard/Premium tiers — useful “gotcha” to mention in the interview. ([Microsoft Learn][1])
* **ADLS Gen2** is enabled via `isHnsEnabled: true`. ([Microsoft Learn][7])
* **Service Bus** roles are assigned via RBAC (**Data Sender/Receiver**), which your Function uses with its **managed identity** (no connection strings). ([Microsoft Learn][9])

**Deploy:**

```bash
az group create -n rg-d365-demo -l westeurope
az deployment group create -g rg-d365-demo -f main.bicep -p prefix=d365demo
```

([Microsoft Learn][10])

## Wire up the API (APIM → Logic App/Function)

### 1) Import a simple backend API into APIM and add policies

Create an `echo` API that proxies your Logic App (HTTP trigger) or the Function’s HTTP endpoint. Add:

* **JWT validation** (Entra ID or your IDP).
* **Rate limiting per subscription** (or per caller claim).

**Policy skeleton (inbound)**:

```xml
<inbound>
  <base />
  <validate-jwt header-name="Authorization" failed-validation-httpcode="401" require-expiration-time="true">
    <openid-config url="https://login.microsoftonline.com/{tenantId}/v2.0/.well-known/openid-configuration" />
    <audiences>
      <audience>api://your-app-id</audience>
    </audiences>
  </validate-jwt>
  <rate-limit-by-key calls="60" renewal-period="60"
     counter-key="@(context.Request.Headers.GetValueOrDefault("X-Client-Id","anon"))" />
</inbound>
```

*Docs:* APIM **policy reference**, **validate‑jwt**, **rate‑limit‑by‑key**. ([Microsoft Learn][1])

> For secrets (e.g., outbound API keys), store them in **Key Vault** and reference as **Named values** in APIM; APIM can use **managed identity** to fetch secrets. ([Microsoft Learn][11])

### 2) Logic App workflow (Consumption)

* Trigger: **When an HTTP request is received**
* Actions:

  1. **Validate JSON** (schema for “Vendor” or “Customer” entity)
  2. **HTTP action to D365 Finance OData** (or use **Fin & Ops connector** if you have an F&O sandbox)
  3. **Send message to Service Bus** (managed identity connection)
  4. **Return 202 Accepted**

Docs you can reference while demoing connectors & options:

* **Fin & Ops Apps (Dynamics 365) connector** for Logic Apps / Power Automate. ([Microsoft Learn][2])
* Logic Apps **Consumption vs Standard**—why you’re using Consumption here. ([Microsoft Learn][12])

> **If you have no D365 sandbox:** use the Logic App’s HTTP action to call a **mock** OData endpoint in your Function; the APIM story still holds.

## Event-driven processing (Azure Function, PowerShell)

Create two simple functions:

1. **HttpIngest** (HTTP trigger): validates input then **sends** to Service Bus (uses MI).
2. **SbProcessor** (Service Bus trigger): reads queue messages, transforms, and writes Parquet/JSON to ADLS Gen2.

* **Service Bus trigger** doc for Functions. ([Microsoft Learn][3])
* **Identity-based connections** (no secrets). Assign **Service Bus Data Sender/Receiver** roles to the Function MI (done in Bicep). ([Microsoft Learn][13])

### HttpIngest

**HttpIngest/function.json**

```json
{
  "bindings": [
    {
      "authLevel": "function",
      "type": "httpTrigger",
      "direction": "in",
      "name": "Request",
      "methods": [ "post" ],
      "route": "HttpIngest"
    },
    { "type": "http", "direction": "out", "name": "Response" },
    {
      "type": "serviceBus",
      "direction": "out",
      "name": "sbOut",
      "queueName": "inbound",
      "connection": "AzureWebJobsServiceBus"
    }
  ]
}
```

**HttpIngest/run.ps1**

```powershell
param($Request, $TriggerMetadata, $sbOut)

# -- Basic validation of required fields
$bodyRaw = $Request.Body
try { $payload = $bodyRaw | ConvertFrom-Json -Depth 20 } catch { $payload = $null }

$required = @('VendorAccount','Name','Currency','CountryRegionId')
$missing  = @()
foreach($r in $required){ if(-not $payload.$r){ $missing += $r } }

if(-not $payload -or $missing.Count -gt 0){
  $msg = @{ error = "Invalid payload"; missing = $missing } | ConvertTo-Json
  Push-OutputBinding -Name Response -Value ([HttpResponseContext]@{ StatusCode = 400; Body = $msg })
  return
}

# -- Enrich (if payload came directly without Logic App)
if(-not $payload.meta){
  $payload = [pscustomobject]@{
    type    = "vendor"
    version = "1.0"
    data    = $payload
    meta    = @{
      source        = "function-http"
      receivedAtUtc = (Get-Date).ToUniversalTime().ToString("o")
      messageId     = [guid]::NewGuid().ToString()
    }
  }
}

# -- Enqueue to Service Bus
$sbOut = $payload | ConvertTo-Json -Depth 20
Push-OutputBinding -Name sbOut -Value $sbOut

# -- 202 Accepted
$resp = [HttpResponseContext]@{
  StatusCode = 202
  Body       = @{
    enqueued = $true
    id       = $payload.meta.messageId
  }
}
Push-OutputBinding -Name Response -Value $resp
```

### SbProcessor

> This function **uses Managed Identity** to write to your ADLS Gen2 account via **Az.Storage**.
> **App settings required** on the Function App:
>
> * `DEMO_STORAGE_ACCOUNT` = name of your ADLS Gen2 storage account
> * `DEMO_STORAGE_CONTAINER` = `landing` (or your preferred container)

**RbAC required**: Assign the Function’s system-assigned identity **Storage Blob Data Contributor** on the storage account.

**SbProcessor/function.json**

```json
{
  "bindings": [
    {
      "type": "serviceBusTrigger",
      "direction": "in",
      "name": "ServiceBusTrigger",
      "queueName": "inbound",
      "connection": "AzureWebJobsServiceBus"
    }
  ]
}
```

**SbProcessor/run.ps1**

```powershell
param($ServiceBusTrigger, $TriggerMetadata)

# Parse message
try { $evt = $ServiceBusTrigger | ConvertFrom-Json -Depth 20 } catch { throw "Message is not valid JSON." }

# MSI login to Azure
Connect-AzAccount -Identity -ErrorAction Stop | Out-Null

$acctName = $env:DEMO_STORAGE_ACCOUNT
if(-not $acctName){ throw "App setting DEMO_STORAGE_ACCOUNT is not set." }
$container = $env:DEMO_STORAGE_CONTAINER
if(-not $container){ $container = "landing" }

# Storage context with MI
$ctx = New-AzStorageContext -StorageAccountName $acctName -UseConnectedAccount

# Ensure container exists
$null = Get-AzStorageContainer -Context $ctx -Name $container -ErrorAction SilentlyContinue
if(-not $?){
  New-AzStorageContainer -Name $container -Context $ctx | Out-Null
}

# Build blob path: vendors/yyyy/MM/dd/{VendorAccount}-{ticks}.json
$dtUtc = Get-Date -AsUTC
$folder = "vendors/{0}" -f $dtUtc.ToString("yyyy/MM/dd")
$fname  = "{0}-{1}.json" -f $evt.data.VendorAccount, $dtUtc.Ticks
$blobPath = "$folder/$fname"

# Serialize and upload (via temp file to avoid module differences)
$content = $evt | ConvertTo-Json -Depth 20
$tmp = Join-Path $env:TEMP ("{0}.json" -f [guid]::NewGuid())
Set-Content -Path $tmp -Value $content -Encoding UTF8

Set-AzStorageBlobContent -File $tmp -Container $container -Blob $blobPath -Context $ctx -Force | Out-Null
Remove-Item $tmp -Force -ErrorAction SilentlyContinue
```

## 3) Minimal APIM product + API + policy (Bicep)

> This module **attaches APIM to your Function** with:
>
> * a **Product** requiring subscriptions,
> * an **API** `vendor-ingest` with `POST /vendors`,
> * **inbound policy**: `validate-jwt`, `rate-limit-by-key`, and injects `x-functions-key` to call your function with a **function key** (you still demo JWT at APIM).
>
> Deploy after your APIM and Function exist.

**apim-demo.bicep**

```bicep
param apimName string
param productDisplayName string = 'D365 Demo'
param productId string = 'd365-demo'
param apiName string = 'vendor-ingest'
param apiDisplayName string = 'Vendor Ingest API'
param apiPath string = 'vendor-ingest'
param operationName string = 'post-vendors'
param operationDisplayName string = 'Submit Vendor'
param functionHostname string // e.g., d365demo-func-abc.azurewebsites.net
param functionKey string // default host or function-level key
param openIdConfigUrl string // e.g., https://login.microsoftonline.com/<tenant>/v2.0/.well-known/openid-configuration
param audience string // e.g., api://<app-registration-client-id>
param rateLimitCalls int = 60
param renewalPeriodSec int = 60

resource apim 'Microsoft.ApiManagement/service@2022-08-01' existing = {
  name: apimName
}

resource nvFuncKey 'Microsoft.ApiManagement/service/namedValues@2022-08-01' = {
  parent: apim
  name: 'func-key'
  properties: {
    displayName: 'Function Default Key'
    value: functionKey
    secret: true
  }
}

resource backendFunc 'Microsoft.ApiManagement/service/backends@2022-08-01' = {
  parent: apim
  name: 'func-backend'
  properties: {
    url: 'https://${functionHostname}/api'
    protocol: 'http'
    tls: { validateCertificateChain: true, validateCertificateName: true }
  }
}

resource api 'Microsoft.ApiManagement/service/apis@2022-08-01' = {
  parent: apim
  name: apiName
  properties: {
    displayName: apiDisplayName
    path: apiPath
    protocols: [ 'https' ]
    serviceUrl: 'https://${functionHostname}/api'
  }
  dependsOn: [ backendFunc ]
}

resource op 'Microsoft.ApiManagement/service/apis/operations@2022-08-01' = {
  parent: api
  name: operationName
  properties: {
    displayName: operationDisplayName
    method: 'POST'
    urlTemplate: '/vendors'
    request: {
      queryParameters: []
      headers: [
        { name: 'Authorization', required: true, type: 'string' }
      ]
      representations: [
        { contentType: 'application/json' }
      ]
    }
    responses: [
      { statusCode: 202, description: 'Accepted' }
      { statusCode: 400, description: 'Bad Request' }
      { statusCode: 401, description: 'Unauthorized' }
    ]
  }
}

resource apiPolicy 'Microsoft.ApiManagement/service/apis/policies@2022-08-01' = {
  parent: api
  name: 'policy'
  properties: {
    format: 'xml'
    value: '''
<policies>
  <inbound>
    <base />
    <validate-jwt header-name="Authorization" require-expiration-time="true" require-scheme="Bearer" failed-validation-httpcode="401">
      <openid-config url="${openIdConfigUrl}" />
      <audiences>
        <audience>${audience}</audience>
      </audiences>
    </validate-jwt>

    <!-- Throttle per subscription -->
    <rate-limit-by-key calls="${rateLimitCalls}" renewal-period="${renewalPeriodSec}"
       increment-condition="@(true)"
       counter-key="@(context.Subscription?.Id ?? "no-sub")" />

    <!-- Function key for backend call (use header instead of query) -->
    <set-header name="x-functions-key" exists-action="override">
      <value>{{func-key}}</value>
    </set-header>

    <!-- Backend: Function -->
    <set-backend-service backend-id="func-backend" />
  </inbound>
  <backend>
    <base />
  </backend>
  <outbound>
    <base />
  </outbound>
  <on-error>
    <base />
  </on-error>
</policies>
'''
  }
}
resource prod 'Microsoft.ApiManagement/service/products@2022-08-01' = {
  parent: apim
  name: productId
  properties: {
    displayName: productDisplayName
    description: 'APIM product for D365 demo'
    terms: 'Use for demo only'
    subscriptionRequired: true
    approvalRequired: false
    state: 'published'
  }
}

resource prodApi 'Microsoft.ApiManagement/service/products/apis@2022-08-01' = {
  parent: prod
  name: api.name
  properties: {}
}
```
